# 📖 Interactive Story Generator

An AI-powered "Choose Your Own Adventure" web app. Enter a theme, and the app generates a unique branching story with multiple paths, choices, and endings — powered by large language models.

🔗 **Live Demo:** [story-generator-ten-snowy.vercel.app](https://story-generator-ten-snowy.vercel.app)

---

## ✨ Features

- 🎨 **Theme-based generation** — enter any theme (fantasy, sci-fi, mystery, etc.) and get a unique story
- 🌳 **Branching narratives** — every choice leads to a different path
- 🏆 **Multiple endings** — including winning and losing outcomes
- ⚡ **Async story generation** — background job processing with real-time status updates
- 💾 **Session-based history** — stories are tied to your browser session via cookies

---

## 🛠️ Tech Stack

**Backend**
- FastAPI (Python)
- SQLAlchemy + SQLite
- LangChain + Groq / OpenAI (LLM-powered story generation)
- Pydantic (structured output validation)

**Frontend**
- React (Vite)
- Axios for API calls

**Deployment**
- Backend hosted on [Render](https://render.com)
- Frontend hosted on [Vercel](https://vercel.com)

## 🚀 Getting Started (Local Development)

### Prerequisites
- Python 3.10+
- Node.js 18+
- An API key from [Groq](https://console.groq.com) (free tier) or [OpenAI](https://platform.openai.com)

### 1. Clone the repository
```bash
git clone https://github.com/Thoyaj1718/Story-Generator.git
cd Story-Generator
```

### 2. Set up the backend
```bash
cd backend
python -m venv venv
venv\Scripts\activate      # Windows
# source venv/bin/activate  # macOS/Linux

pip install -r requirements.txt
```

Create a `.env` file inside `backend/` with:
```env
DATABASE_URL=sqlite:///./database.db
API_PREFIX=/api
DEBUG=True
ALLOWED_ORIGINS=http://localhost:5173
GROQ_API_KEY=your_groq_api_key_here
```

Run the backend:
```bash
uvicorn main:app --reload
```
The API will be live at `http://127.0.0.1:8000` — visit `/docs` for the interactive Swagger UI.

### 3. Set up the frontend
Open a new terminal:
```bash
cd frontend
npm install
npm run dev
```
The app will be live at `http://localhost:5173`.

## 🔐 API Authentication

No login or API key is required from end users. Each browser session is tracked using an **HTTP-only session cookie**, automatically set by the backend on the first request. This cookie associates all generated stories with that specific session, so returning users can access their own story history without needing to sign in.

Server-side, the backend authenticates with the LLM provider (Groq or OpenAI) using an API key stored securely as an environment variable (`GROQ_API_KEY` / `OPENAI_API_KEY`). This key is never exposed to the frontend or the client — all LLM requests are proxied through the backend.

## 📚 API Documentation

Base URL (local): `http://127.0.0.1:8000/api`
Base URL (production): `https://story-generator-backend-q5dl.onrender.com/api`

Interactive Swagger docs are also auto-generated by FastAPI at `/docs` on either base URL.

### 1. Create a New Story

```
POST /api/stories/create
```

**Request Body**

| Field   | Type   | Required | Description                        |
|---------|--------|----------|------------------------------------|
| `theme` | string | Yes      | The theme for the story (e.g. `"fantasy"`, `"space exploration"`) |

**Response — `201 Created`**

| Field        | Type   | Description                                  |
|--------------|--------|-----------------------------------------------|
| `job_id`     | string | Unique ID to poll for generation status       |
| `status`     | string | Initial status, usually `"processing"`        |
| `created_at` | string | ISO timestamp of job creation                 |

### 2. Check Job Status

```
GET /api/jobs/{job_id}
```

**Path Parameters**

| Param    | Type   | Description                         |
|----------|--------|---------------------------------------|
| `job_id` | string | The job ID from the create endpoint   |

**Response — `200 OK`**

| Field      | Type            | Description                                    |
|------------|-----------------|--------------------------------------------------|
| `job_id`   | string          | The job's ID                                     |
| `status`   | string          | One of: `processing`, `completed`, `failed`      |
| `story_id` | integer \| null | Set once generation completes successfully        |
| `error`    | string \| null  | Populated if `status` is `failed`                  |

### 3. Get Complete Story

```
GET /api/stories/{story_id}/complete
```

**Path Parameters**

| Param      | Type    | Description                                      |
|------------|---------|----------------------------------------------------|
| `story_id` | integer | The story's ID (from job status once completed)    |

**Response — `200 OK`**

| Field        | Type    | Description                               |
|--------------|---------|---------------------------------------------|
| `id`         | integer | Story ID                                    |
| `title`      | string  | AI-generated story title                    |
| `session_id` | string  | Session the story belongs to                |
| `created_at` | string  | ISO timestamp                               |
| `root_node`  | object  | The starting node of the story (see below)  |

**Story Node object**

| Field              | Type          | Description                                              |
|--------------------|---------------|------------------------------------------------------------|
| `id`               | integer       | Node ID                                                    |
| `content`          | string        | Narrative text for this node                               |
| `is_ending`        | boolean       | Whether this node is an ending                              |
| `is_winning_ending` | boolean       | Whether this ending is a "win" (only relevant if `is_ending` is true) |
| `options`          | array \| null | Available choices; `null`/empty if `is_ending` is true       |

**Option object (within `options`)**

| Field     | Type    | Description                              |
|-----------|---------|---------------------------------------------|
| `text`    | string  | Choice text shown to the player             |
| `node_id` | integer | ID of the story node this choice leads to   |

**Error — `404 Not Found`**

| Field    | Value                 |
|----------|------------------------|
| `detail` | `"Story not found"`   |

### Typical Frontend Flow

| Step | Action                                                                 |
|------|--------------------------------------------------------------------------|
| 1    | User submits a theme → `POST /api/stories/create` → receive `job_id`    |
| 2    | Frontend polls `GET /api/jobs/{job_id}` until `status` is `completed` or `failed` |
| 3    | Once `completed`, frontend calls `GET /api/stories/{story_id}/complete` |
| 4    | The full branching story is rendered and navigated client-side — no further API calls needed per choice |

### Error Handling

| Status Code | Meaning                                         |
|-------------|----------------------------------------------------|
| `404`       | Resource (story, job) not found                    |
| `422`       | Validation error (e.g. missing `theme` field)      |
| `500`       | Server error (e.g. LLM API failure, invalid key)   |

### Environment Variables (Backend)

| Variable          | Description                                              |
|--------------------|-------------------------------------------------------------|
| `DATABASE_URL`     | Database connection string (SQLite by default)              |
| `API_PREFIX`        | Prefix for all API routes (default: `/api`)                  |
| `ALLOWED_ORIGINS`   | Comma-separated list of allowed frontend origins (CORS)      |
| `GROQ_API_KEY`      | API key for Groq-hosted LLM (free tier)                       |
| `OPENAI_API_KEY`    | Optional fallback API key for OpenAI                          |

## 🌐 Deployment

- **Backend (Render):** deployed as a Python web service, with environment variables configured in the Render dashboard.
- **Frontend (Vercel):** deployed as a static Vite build, with `VITE_API_URL` (or the equivalent config in `util.js`) pointing to the live Render backend URL.

Make sure `ALLOWED_ORIGINS` on the backend includes your deployed frontend's URL to avoid CORS errors.
